# راهنمای نگهداری Eventum HQ (OPERATIONS)

این سند برای باربد و فرید است: نصب روی سرور، به‌روزرسانی، بکاپ و بازیابی، و رفع مشکل‌های رایج.
همهٔ دستورها را **کامل و به همان ترتیب** اجرا کنید. هر بلوک کد یک دستور است.

> ⚠️ ربات اصلی (`@EventumHQBot`) فقط روی سرور اجرا شود. برای آزمایش روی کامپیوتر خودتان همیشه از ربات تست و یک `.env` جدا استفاده کنید. **یک توکن را هم‌زمان در دو جا اجرا نکنید**؛ تلگرام خطای `Conflict` می‌دهد.

---

## ۱. نیازها

**سرور (از لیمینال):**
- Ubuntu 22.04 یا 24.04
- 1 vCPU، 1GB RAM، حدود 10GB دیسک
- دسترسی خروجی HTTPS به `api.telegram.org` (هیچ پورت ورودی لازم نیست)
- دسترسی SSH برای باربد و فرید

**تلگرام:**
- توکن ربات اصلی از @BotFather
- کانال خصوصی آرشیو، که ربات در آن **ادمین** است
- گروه تیم Eventum Space، که ربات عضو آن است (privacy mode روشن بماند)

---

## ۲. نصب اول روی سرور

### ۲.۱ ورود به سرور
روی کامپیوتر خودتان (PowerShell):
```bash
ssh USER@SERVER_IP
```
`USER` و `SERVER_IP` را لیمینال می‌دهد.

### ۲.۲ نصب Docker (فقط بار اول)
```bash
curl -fsSL https://get.docker.com | sudo sh
```
```bash
sudo usermod -aG docker $USER
```
یک بار از سرور خارج شوید (`exit`) و دوباره وارد شوید. بعد امتحان کنید:
```bash
docker compose version
```

### ۲.۳ آوردن کد روی سرور
پروژه هنوز remote در GitHub ندارد. پیشنهاد: یک **repository خصوصی** در GitHub بسازید و کد را push کنید. بعد روی سرور:
```bash
git clone https://github.com/OWNER/eventum-hq.git
```
```bash
cd eventum-hq
```
(راه دیگر: پوشهٔ پروژه را بدون `.env`، `.venv` و `data/` زیپ کنید و با `scp` روی سرور بفرستید.)

### ۲.۴ ساخت `.env`
```bash
cp .env.example .env
```
```bash
nano .env
```
مقادیر را پر کنید:

| کلید | مقدار روی سرور |
|---|---|
| `BOT_TOKEN` | توکن **ربات اصلی** |
| `OWNER_TELEGRAM_ID` | شناسهٔ عددی تلگرام باربد |
| `TEAM_GROUP_ID` | شناسهٔ گروه تیم (عدد منفی، مثل `-100…`) |
| `ARCHIVE_CHANNEL_ID` | شناسهٔ کانال آرشیو (عدد منفی، مثل `-100…`) |
| `DATABASE_URL` | دست نزنید: `sqlite+aiosqlite:///data/eventum.db` |
| `TELEGRAM_PROXY` | **خالی** (سرور فیلتر نیست) |
| `LOG_LEVEL` | `INFO` |

ذخیره در nano: `Ctrl+O` و Enter، خروج: `Ctrl+X`.

> نکته: اگر شناسهٔ گروه یا کانال را نمی‌دانید، `TEAM_GROUP_ID` و `ARCHIVE_CHANNEL_ID` را خالی بگذارید، ربات را اجرا کنید و ربات را به گروه/کانال اضافه کنید. ربات شناسه را برای OWNER می‌فرستد. بعد مقدار را در `.env` بگذارید و ربات را دوباره اجرا کنید (بخش ۳).

### ۲.۵ اجرا
```bash
docker compose up -d --build
```
بررسی لاگ (برای خروج از لاگ `Ctrl+C`؛ ربات روشن می‌ماند):
```bash
docker compose logs -f --tail 100
```
باید خط‌های `database migrations are up to date` و `connected as @EventumHQBot` را ببینید.

در تلگرام به ربات `/start` و بعد `/health` بزنید.

---

## ۳. کارهای روزمره

| کار | دستور (داخل پوشهٔ `eventum-hq`) |
|---|---|
| دیدن لاگ زنده | `docker compose logs -f --tail 100` |
| وضعیت کانتینر | `docker compose ps` |
| ری‌استارت ربات | `docker compose restart` |
| خاموش‌کردن ربات | `docker compose down` |
| روشن‌کردن دوباره | `docker compose up -d` |

- لاگ‌های فایل در `data/logs/eventum.log` هستند (۷ فایل چرخشی ۱۰ مگابایتی).
- `restart: unless-stopped` یعنی اگر سرور ری‌استارت شود یا برنامه بیفتد، ربات خودش دوباره روشن می‌شود.

### دستورهای مدیر سیستم در تلگرام (فقط OWNER و SYSTEM_ADMIN)
- `/health`: مدت روشن‌بودن، آخرین tick زمان‌بند (باید کمتر از ۵ دقیقه پیش باشد)، حجم دیتابیس، آخرین بکاپ، تعداد اعلان‌های در صف و ناموفق.
- `/backup`: همین الان بکاپ می‌گیرد و فایل فشرده (`.db.gz`) را برایتان می‌فرستد.

### هشدارها
- **خطای برنامه:** هر خطای پیش‌بینی‌نشده برای SYSTEM_ADMINها پیام «🚨 خطا در ربات» می‌فرستد؛ از هر نوع خطا حداکثر یک پیام در ۱۰ دقیقه. جزئیات کامل در لاگ است.
- **Heartbeat:** اگر زمان‌بند بیش از ۵ دقیقه کار نکرده باشد (مثلاً سرور خاموش بوده)، در اولین فرصت هشدار می‌آید.
- ساعات سکوت (۲۳ تا ۹) روی این هشدارها هم اعمال می‌شود؛ پیام ساعت ۹ می‌رسد.

---

## ۴. به‌روزرسانی

قبلش یک بکاپ بگیرید (در تلگرام `/backup`). بعد:
```bash
cd eventum-hq
```
```bash
git pull
```
```bash
docker compose up -d --build
```
migrationهای دیتابیس هنگام شروع خودکار اجرا می‌شوند. با `docker compose logs -f --tail 100` مطمئن شوید ربات بالا آمده.

---

## ۵. بکاپ

| نوع | زمان | کجا |
|---|---|---|
| روزانه | هر روز ۰۴:۰۰ تهران | `data/backups/eventum-YYYYMMDD.db` (۱۴ نسخهٔ آخر می‌ماند) |
| هفتگی | جمعه ۰۴:۳۰ | فایل فشرده در چت خصوصی SYSTEM_ADMINها (نسخهٔ بیرون از سرور) |
| دستی | هر وقت | `/backup` در تلگرام |

اگر بکاپ فشرده بیشتر از ۴۵ مگابایت شود، ربات هشدار می‌دهد و فقط روی سرور نگهش می‌دارد. در این حالت فایل را با `scp` بردارید:
```bash
scp USER@SERVER_IP:~/eventum-hq/data/backups/eventum-YYYYMMDD.db .
```

> **محدودیت آگاهانهٔ v0:** خود فایل‌ها (ویدیو، عکس، کاور) فقط در کانال آرشیو تلگرام هستند. بکاپ دیتابیس فقط «آدرس» آن‌ها (`file_id`) را دارد. **نسخهٔ مستر فایل‌ها را جای دیگری هم نگه دارید** (مثلاً درایو تیم). کانال آرشیو را هرگز پاک نکنید.

---

## ۶. بازیابی از بکاپ

۱. ربات را خاموش کنید:
```bash
docker compose down
```
۲. از دیتابیس فعلی یک کپی ایمنی بگیرید:
```bash
cp data/eventum.db data/eventum-before-restore.db
```
۳. فایل‌های WAL قدیمی را پاک کنید (اگر وجود دارند):
```bash
rm -f data/eventum.db-wal data/eventum.db-shm
```
۴. بکاپ را جای دیتابیس بگذارید. از بکاپ روزانه:
```bash
cp data/backups/eventum-YYYYMMDD.db data/eventum.db
```
یا از فایل فشرده‌ای که در تلگرام گرفته‌اید (اول آن را با `scp` در پوشهٔ `data/` بگذارید):
```bash
gunzip -c data/eventum-YYYYMMDD.db.gz > data/eventum.db
```
۵. ربات را روشن کنید:
```bash
docker compose up -d
```
۶. در تلگرام `/health` بزنید و «📋 کارهای من» را ببینید.

> کارهایی که بعد از زمان بکاپ ثبت شده‌اند از دست می‌روند. فایل‌های آرشیو تلگرام سر جایشان هستند.

**قبل از پایلوت، این بازیابی را یک بار روی ربات تست امتحان کنید** (چک‌لیست بخش ۸).

---

## ۷. مشکل‌های رایج

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| ربات جواب نمی‌دهد | کانتینر خاموش است | `docker compose ps` و بعد `docker compose up -d` |
| در لاگ `Conflict: terminated by other getUpdates` | همین توکن جای دیگری هم اجرا شده | نسخهٔ روی کامپیوتر خودتان را خاموش کنید |
| در لاگ `Unauthorized` | توکن اشتباه است | `BOT_TOKEN` را در `.env` درست کنید و `docker compose up -d` |
| `Cannot reach api.telegram.org` | اینترنت یا proxy | روی سرور `TELEGRAM_PROXY` باید خالی باشد |
| تحویل فایل خطا می‌دهد | `ARCHIVE_CHANNEL_ID` خالی یا ربات ادمین کانال نیست | ربات را ادمین کانال کنید و شناسه را در `.env` بگذارید |
| پیام‌های گروه نمی‌آید | `TEAM_GROUP_ID` خالی یا اشتباه | شناسه را درست کنید و ری‌استارت |
| `/health` می‌گوید tick دیر است | برنامه گیر کرده | `docker compose restart` و بررسی لاگ |

---

## ۸. چک‌لیست قبل از پایلوت (هندآف ۱۱.۳)

- [ ] ربات اصلی و ربات تست جدا هستند (دو توکن، دو `.env`)
- [ ] کانال آرشیو خصوصی ساخته شده و ربات در آن ادمین است
- [ ] ربات به گروه Eventum Space اضافه شده، privacy mode روشن است و `TEAM_GROUP_ID` درست است
- [ ] هر ۶ نفر وارد شده‌اند و نقش‌ها مطابق بخش ۳.۱ هندآف تأیید شده‌اند
- [ ] یک بکاپ دستی (`/backup`) گرفته و بازیابی آن یک بار روی ربات تست امتحان شده (بخش ۶)
- [ ] هشدار به SYSTEM_ADMIN می‌رسد. راه ساده: `docker compose stop`، ۶ دقیقه صبر، `docker compose start`. باید پیام «⚠️ زمان‌بندی ربات … دقیقه کار نکرده بود» بیاید (بیرون از ساعات سکوت). هشدار «🚨 خطا در ربات» با تست‌های خودکار پوشش داده شده است.
- [ ] `/health` سالم است و آخرین tick کمتر از ۵ دقیقه پیش است
- [ ] تیم پیام `/help` را دیده است

## ۹. خروج یک عضو از تیم (Offboarding)

۱. «👥 تیم» ← «👤 اعضای تیم» ← نام فرد ← «⛔️ غیرفعال‌سازی» ← تأیید.
۲. ربات نشان می‌دهد کدام دسترسی‌های او (مثلاً «بررسی مرحلهٔ اول» یا «ثبت انتشار») حالا هیچ عضو فعال دیگری ندارد. این را به باربد بگویید تا جایگزین تعیین شود.
۳. کارهای بازش را بسپارید: «📦 انتقال همهٔ کارها به…» یا روی هر تسک جدا بزنید. کارهای تکراری او را هم یکی‌یکی به نفر جدید بدهید؛ تا وقتی مسئول ندارند، ساخته نمی‌شوند.
۴. تا وقتی کاری باقی مانده، «👥 تیم» با ⚠️ یادآوری می‌کند.

نام و تاریخچهٔ کارهای فرد در همهٔ سوابق می‌ماند. اگر برگشت، دوباره `/start` می‌زند و باربد درخواستش را تأیید می‌کند.
